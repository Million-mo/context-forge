# Context Forge — 产品价值分析

## 一句话定位

**Context Forge 是一个面向 AI 编程助手的上下文生命周期管理系统——在上下文窗口有限的前提下，让 AI 能"记住"更长的对话历史、更精确地召回关键信息，并大幅降低 token 成本。**

---

## 解决的核心问题

AI 编程助手的上下文窗口是**硬约束**。一次典型的编程会话很容易突破 128K tokens，导致：

| 痛点 | 表现 | Context Forge 的对策 |
|------|------|---------------------|
| **上下文溢出** | 对话过长，早期决策和文件状态被挤出窗口，AI 反复问同样的问题 | 轮次摘要 + 历史注入 |
| **Token 浪费** | `read_file` / `grep` / `glob` 的原始输出在上下文中反复出现 | 衰减式工具输出压缩（4 级） |
| **长会话退化** | 超过 50 轮后，AI 决策质量明显下降 | Resume 快照 + 意图驱动召回 |
| **重复探索** | 新会话中，AI 重新探索已读过的文件 | FTS5 内容索引 + BM25/RRF 搜索 |
| **安全风险** | 沙箱执行被注入危险命令、路径穿越 | 环境净化 + 路径穿越防护 |

---

## 产品架构：三条产品线

```
┌─────────────────────────────────────────────────────────────────┐
│                     Context Forge                               │
├─────────────────┬───────────────────┬───────────────────────────┤
│  ctx_plugin     │  mcp_ctx_tool     │  mcp_ctx_summary          │
│  (实时压缩层)    │  (执行+内容索引)   │  (短期会话记忆)            │
├─────────────────┼───────────────────┼───────────────────────────┤
│ • LLM 摘要生成  │ • 多语言沙箱执行   │ • 意图驱动 LLM 召回        │
│ • 工具输出压缩  │ • FTS5 内容索引    │ • FTS5 摘要搜索            │
│ • RTK 命令重写  │ • 会话事件追踪     │ • 原始消息回溯（无损）      │
│ • Caveman 模式  │ • 系统诊断        │                           │
│ • 安全策略引擎  │ • Web 抓取+索引   │                           │
└─────────────────┴───────────────────┴───────────────────────────┘
        实时               工具+知识库              短期记忆
```

三条产品线各自独立价值，又可以组合使用：

1. **`ctx_plugin`**（无需 MCP）—— 实时上下文压缩。装上即用，在消息进入 LLM 之前完成压缩和摘要生成。
2. **`mcp_ctx_tool`**（独立 MCP）—— 沙箱代码执行 + 可搜索的内容索引（项目知识库）。任何支持 MCP 的 agent 都可调用。会话事件追踪提供运维级遥测。
3. **`mcp_ctx_summary`**（独立 MCP）—— **短期会话记忆：压缩存储 + 无损召回。** 由 `ctx_plugin` 自动产生每轮 LLM 摘要，AI 可以按意图搜索并取回完整的原始消息。解决"刚才我们做了什么"类问题，不跨会话持久化。

### 两个 MCP 的边界

| 维度 | mcp_ctx_tool | mcp_ctx_summary |
|------|-------------|----------------|
| **数据来源** | 用户主动调用 `ctx_index` / `ctx_fetch` | `ctx_plugin` 自动生成每轮 LLM 摘要 |
| **存储** | `content.db`（FTS5 porter+trigram 双索引）+ sessions DB | `summaries.db`（FTS5 摘要索引 + 原始消息表） |
| **搜索类型** | BM25/RRF 关键词搜索 → 内容片段 | FTS5 搜索 + LLM 生成式召回 → 可读回忆 |
| **记忆性质** | 项目知识库（跨会话持久） + 工具遥测 | 短期工作记忆（当前会话内） |
| **"之前做了什么"** | `ctx_session` → 结构化统计报告 | `ctx_recall` → 语义化自然语言回忆 |

> **重叠澄清：** `ctx_session` 的 resume 快照和 `ctx_recall` 的语义召回都是回答"之前做了什么"——
> 前者是结构化的"目录"（文件操作、Git 操作、工具统计），后者是细粒度的"详情"（"那个 bug 怎么修的"）。
> 二者互补，不冲突。未来可考虑将 session 分析统一到 summary 侧，让 `mcp_ctx_tool` 回归纯"执行 + 索引"。

## 差异化价值点

### 1. 上下文节省不是"事后压缩"，而是"源头治理"

大多数方案在上下文满时才开始截断。Context Forge 采用**全生命周期管理**：

```
消息产生 → 分类萃取(session extract) → 衰减压缩(decay scoring)
         → LLM 摘要生成 → 结构化存储
         → 下次对话时主动注入历史摘要
         → 需要细节时通过 FTS5 精确召回
```

### 2. 双 FTS5 索引 + RRF 融合搜索

`ContentStore` 同时维护 `porter` 分词和 `trigram` 两个 FTS5 索引，搜索时用 RRF（Reciprocal Rank Fusion）合并排序。这比单一 BM25 搜索提供了更好的召回率——porter 抓语义匹配，trigram 抓模糊匹配。

`summaries.db` 同理，schema 中内置了 FTS5 虚拟表 + 触发器自动同步，插入即索引。

### 3. 衰减式压缩不是"一刀切"

`ctx_plugin/transform.ts` 对 `read`/`grep`/`glob`/`webfetch` 等工具输出按**时间衰减 + 距离衰减 + 频率衰减**三维打分，区分 4 个压缩等级：

| 等级 | 得分 | 效果 |
|------|------|------|
| `full` | <2 | 保留全部输出 |
| `summary` | <5 | 保留头尾各 3 行 + 总行数 |
| `placeholder` | <8 | 保留匹配数量和前 5 条摘要 |
| `minimal` | ≥8 | 仅保留工具名和参数 |

**核心洞察：** 刚读取的文件应该完整保留，10 轮前重复读取的文件应该几乎完全压缩。这是对 AI 注意力机制的工程化模拟。

### 4. Resume 快照：长会话的"断点续传"

`snapshot.ts` 将数百个会话事件压缩为结构化的"目录"——文件操作、Git 操作、关键决策、错误、任务列表——每个类别去重后摘要。AI 可以在上下文中快速重建会话状态，需要的细节再通过 `ctx_content_search` 召回。

### 5. 安全不是附加功能，是基础设施

`executor.ts` 的 `#buildSafeEnv` 拒绝 30+ 危险环境变量（`LD_PRELOAD`、`NODE_OPTIONS`、`PYTHONSTARTUP`、`RUSTFLAGS` 等），Windows 下还额外过滤 `Microsoft\WindowsApps` 伪路径。路径穿越检测在 `executeFile` 中双重校验。

### 6. 跨平台 + 11 语言

沙箱执行器在 Linux / macOS / Windows 上有不同的 shell 检测、PATH 处理、进程管理逻辑。11 种语言每种都有运行时自动检测和降级策略。

## 量化价值（估算）

基于系统设计的估算，非实测数据：

| 指标 | 典型节省 | 机制 |
|------|---------|------|
| Token 消耗 | 减少 40-65% | 工具输出压缩 + Caveman 模式 |
| 有效上下文 | 延长 3-5x | 摘要注入替代原始消息 |
| 重复探索 | 减少 80%+ | FTS5 索引复用已读内容 |
| 长会话找回时间 | 从"翻几十轮"到"一次搜索" | Intent-driven recall |

## 适用场景

| 场景 | 痛点 | 核心价值组件 |
|------|------|-------------|
| **大型重构**（50+ 轮对话） | 上下文溢出，忘掉早期决策 | transform 摘要 + ctx_recall |
| **多项目切换** | 重复探索项目结构 | FTS5 内容索引 + ctx_content_search |
| **代码审查** | 大量文件读取消耗 token | 衰减压缩 |
| **安全敏感项目** | 担心沙箱逃逸 | 安全策略 + 环境净化 |
| **多语言项目** | 需要执行多种语言代码 | 沙箱执行器（11 种语言） |

---

## 竞争定位

| 对比维度 | 传统做法（手动截断） | Context Forge |
|----------|---------------------|---------------|
| 压缩时机 | 事后、手动 | 实时、自动、分级 |
| 存储 | 无 | SQLite FTS5 双索引 |
| 召回 | 翻聊天记录 | 语义搜索 + LLM 生成召回 |
| 安全 | 依赖系统隔离 | 多层净化 + 路径保护 |
| 可组合性 | — | Plugin + MCP 独立可插拔 |

---

## 总结

**Context Forge 不是又一个"上下文压缩"工具——它是一个完整的上下文生命周期平台：在消息进入 LLM 前压缩、在会话中追踪、在需要时召回。三条产品线独立可插拔：`ctx_plugin` 做实时压缩，`mcp_ctx_tool` 做执行和知识库索引，`mcp_ctx_summary` 做短期会话记忆（压缩存储 + 无损召回）。**
